# Multibrawn · שבת חתן

אתר התוכן והמכירה של המדריך לשבת חתן.

## המשפך

```
public/index.html
   ├── "המדריך התפעולי המלא"  →  תשלום ב-GROW
   │                               └── thank-you.html + מייל + התראה לערדית
   │                                     └── קישור אישי → functions/guide.js
   ├── "המדריך החינמי"        →  free-guide.html
   │                               └── צ'אטבוט + CTA לשאלון ולמדריך בתשלום
   └── "משחקי החיבור"         →  games.html
```

בכל דף יש כפתור חזרה עקבי לדף הבית, באותו מיקום ובאותו עיצוב (`.home-link` ב-`brand.css`).

## מבנה

```

├── games.html                   משחקי החיבור
├── thank-you.html               דף תודה אחרי תשלום

└── assets/
    ├── brand.css                כל הטוקנים והטיפוגרפיה

├── grow-webhook.js              קבלת תשלום ומסירה
├── guide.js                     הגשת המדריך אחרי אימות
├── chat.js                      פרוקסי לצ'אטבוט
```

**למה `public/` ולא שורש הריפו:** כל מה שבתוך תיקיית הפרסום מוגש כקובץ סטטי. עם `publish = "."` הקובץ `netlify/functions/private/Guide.html` היה ניתן להורדה בחינם. תיקיית פרסום נפרדת הופכת את זה לבלתי אפשרי מבנית, במקום להסתמך על כלל הפניה שיישאר נכון.

## מסירת המדריך אחרי תשלום

לקוח משלם ב-GROW ומקבל את המדריך בשלוש דרכים עצמאיות:

1. **דף התודה** — קישור על המסך, מיד
2. **אימייל** — עותק שמור, נשלח תוך שניות
3. **וואטסאפ ידני** — ערדית מקבלת התראה עם הודעה מוכנה, לוחצת ושולחת

**אין אינטגרציה עם Twilio ואין אינטגרציה עם Meta.** וואטסאפ נשלח ידנית מהטלפון של ערדית, דרך קישור `wa.me` מוכן שמגיע במייל ההתראה.

### סדר הפעולות ב-`grow-webhook`

אימות חתימה → מניעת כפילות → יצירת קישור אישי → שתי שליחות במקביל → כתיבה אחת לגיליון → **תמיד 200**.

ה-200 מכוון: כל תשובה אחרת תגרום ל-GROW לנסות שוב, והלקוח יקבל את המדריך פעמיים. את הכישלונות רואים בגיליון, לא דרך קוד התגובה.

הקישור האישי הוא `HMAC-SHA256(transaction_id, TOKEN_SECRET)`, 16 תווים base64url, מושווה ב-`timingSafeEqual`. בלי תפוגה.

דף התודה לא יכול לחשב את הטוקן, כי הסוד לא יוצא מהשרת. לכן קישור בלי טוקן מאומת מול הגיליון — רק עסקה שה-webhook באמת רשם מקבלת גישה.

### תקציב זמן

Netlify עוצר פונקציה סינכרונית אחרי 10 שניות. ה-webhook עובד בתוך תקציב של 7.5 שניות שכל הניסיונות החוזרים מתחלקים בו. **timeout גורם ל-GROW לשלוח שוב**, ואם הגיליון לא זמין גם בדיקת הכפילות לא עובדת — הלקוח היה מקבל מייל כפול. שלוש בדיקות שומרות על הגבול.

### הגיליון — לשונית "מכירות"

| עמודה | תוכן |
|---|---|
| A | תאריך ושעה |
| B | מזהה עסקה |
| C | שם |

## הצ'אטבוט

הדף לא יכול לקרוא ל-Anthropic ישירות — זה היה מחייב לשלוח מפתח API לדפדפן. `chat.js` הוא פרוקסי, ובסיס הידע והפרומפט יושבים בו ולא בקוד המקור של הדף.

בלי `ANTHROPIC_API_KEY` מוגדר הפונקציה מחזירה 503, והדף נופל חזרה לשש התשובות המובנות שלו — שעובדות בלי רשת בכלל.

## משתני סביבה

Netlify → Site settings → Environment variables. אף אחד מהם לא מופיע בקוד ולא נשלח לדפדפן.

| משתנה | תוכן |
|---|---|
| `RESEND_API_KEY` | מפתח Resend |
| `FROM_EMAIL` | `noreply@multibrawn.co.il` |
| `ARDIT_EMAIL` | כתובת ההתראות של ערדית |
| `ARDIT_WHATSAPP` | `972523983394` |
| `GROW_WEBHOOK_SECRET` | סוד לאימות הפנייה מ-GROW |
| `TOKEN_SECRET` | `openssl rand -base64 48` |
| `GOOGLE_SA_EMAIL` | כתובת ה-service account |
| `GOOGLE_SA_PRIVATE_KEY` | המפתח הפרטי |
| `SHEET_ID` | מזהה הגיליון |
| `ANTHROPIC_API_KEY` | לצ'אטבוט (אופציונלי) |

**החלפת `TOKEN_SECRET` מבטלת כל קישור שכבר נשלח ללקוחות.**

## המעבר ל-Netlify — סדר הפעולות

האתר מוגש היום מ-GitHub Pages, ו-Pages לא מריץ קוד שרת. הסדר חשוב, אחרת יש זמן שבו הדומיין לא עובד:

1. לחבר את הריפו ל-Netlify ולוודא ש-deploy preview עולה
2. להגדיר את כל משתני הסביבה
3. להעביר את רשומות ה-DNS של `guide.multibrawn.co.il` ל-Netlify
4. **רק אז** למזג — ולמחוק את `CNAME`, שרלוונטי רק ל-GitHub Pages

`CNAME` נשאר בריפו בכוונה עד שלב 4.
